- [ ] Keyboard shortcuts (plan, needs a spec before work starts):
  - Scope, first version: the study screen only. `Space` flips the card, `1` / `2` = "I don't know" / "I know", `←` / `→` previous / next card, `?` opens a help dialog listing the shortcuts. No global shortcuts yet (they clash with browser and screen reader keys).
  - Accessibility (WCAG 2.2): single-character shortcuts must be switchable off or active only while the component has focus (SC 2.1.4, level A, https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html). Plan: active only while the study card area has focus, plus a "keyboard shortcuts" on/off setting. Never fire inside `input`/`textarea`/`contenteditable`. Every shortcut also has a visible button (shortcuts are a speed-up, never the only way).
  - Discoverability: `aria-keyshortcuts` on the buttons (https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-keyshortcuts) and the help dialog with the helm `kbd` component (already in `shared/ui/kbd`).
  - Implementation: a host listener on the study component (`host: { '(keydown)': ... }`, https://angular.dev/guide/components/host-elements), no library at first. Use `event.key` for characters and check it on a Turkish Q and F layout and a Polish layout; ignore events with `ctrlKey`/`metaKey`/`altKey` so browser shortcuts keep working.
  - Tests: unit tests dispatching `KeyboardEvent`s on the component (flip, know/don't know, ignored in an input, ignored when switched off); later an e2e run with keyboard only.
  - Open questions: do shortcut labels need translations (Transloco keys for the help dialog: yes)? Where does the on/off setting live before user settings exist (local storage)?
